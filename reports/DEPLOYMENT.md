## Устройство публикации

React и FastAPI работают на одном домене. Браузер отправляет фото Python-серверу по HTTPS; инференс выполняется на CPU хостинга. Приложение обрабатывает загруженные фото в оперативной памяти, не сохраняет их автоматически и не вызывает внешние AI API. После публикации обработка происходит на сервере, а не на компьютере посетителя.

Прежняя сборка использовала контейнерный сервис `mogzilla`. В `vercel.json` указаны `runtime: "container"`, `entrypoint: "Dockerfile.vercel"` и перенаправление всех запросов в этот сервис.

Файлы текущего комплекта:

- `Dockerfile.vercel`: сборка React через Node 24 и pnpm, Python 3.12, CPU PyTorch и torchvision из официального CPU-индекса, системные библиотеки GL/GLES, EGL и PortAudio для MediaPipe. Приложение запускается от отдельного пользователя.
- `requirements-runtime.txt`: зависимости инференса без инструментов обучения и тестирования.
- `scripts/download_holistic_models.py`: загрузка закреплённых upstream-моделей с проверкой SHA-256.
- `training/checkpoints/holistic/personal-preference.json`, `personal-preference.npz`, `personal-visual.pt`: текущие настройки и дообученные веса.
- `scripts/serve_mogzilla.py`: проверка собранного интерфейса, файлов ресурсов и загрузки ожидаемой ревизии модели перед запуском. Несовпадение ревизии или отсутствие модели останавливает запуск.
- `.dockerignore` и `.vercelignore`: ограничение состава сборки; датасеты, архивы, окружения и экспериментальные подборки не входят в текущий образ.

В production работает один процесс приложения с ограничением параллельных запросов. Он слушает `0.0.0.0`, порт задаётся переменной `PORT` и по умолчанию равен 80 в образе.

## Проверки

Из корня репозитория с установленными зависимостями и собранным интерфейсом:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.serve_mogzilla --check
```

Проверка текущего демо:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_mogzilla_deployment https://mogzilla.2-27-32-143.sslip.io/
```

Скрипт проверяет HTML и основные ресурсы интерфейса, `/api/holistic/model`, `/api/holistic/method` и реальный POST в `/api/holistic/analyze`. Для анализа используется только фотография, уже опубликованная в галерее приложения: `frontend/src/assets/examples/example-03.png`.

При проверке прежнего публичного выпуска были получены следующие результаты.

- модель готова, активная ревизия `33c59a04cba4`;
- три основных ресурса интерфейса доступны;
- контрольная фотография получила **10.0**, вернулись **478 точек** и **8 областей**;
- через браузер проверен путь «Анализ → Выбрать фото → результат»: категория **true adam**, соответствующий маскот и диапазон кадрирования **9.8–10.0**;
- при финальной проверке в production-логах за последние 10 минут не обнаружено записей уровня `error` или `fatal`.

Это проверка работоспособности опубликованного приложения, а не дополнительная оценка точности модели. Оценка и технический разброс относятся к конкретному снимку.

## Сборка контейнера вручную

На компьютере с Docker:

```text
docker build -f Dockerfile.vercel -t mogzilla .
docker run --rm -p 8000:80 mogzilla
```

Приложение будет доступно по `http://127.0.0.1:8000`. Для проверки запущенного контейнера:

```text
python -m scripts.check_mogzilla_deployment http://127.0.0.1:8000
```

Актуальный образ собран и проверен на Linux в Vercel; локальная Docker-сборка на Windows не выполнялась.
